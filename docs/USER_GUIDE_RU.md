# VASYA GNS LAB 1.1.0 — руководство пользователя

VASYA GNS LAB — менеджер учебной сетевой лаборатории для GNS3: каталог из 186 устройств, автоматическая загрузка
и установка проверенных образов, проверка запуском, восстановление, журнал, диагностика и чистое удаление.
Всё, что создаёт VASYA, лежит в **одной папке** (по умолчанию `~/VASYA-GNS-LAB`, на Windows
`%LOCALAPPDATA%\VASYA-GNS-LAB`) и записывается в квитанции (State/receipts).

## Экраны
| Экран | Что делает |
|---|---|
| Главная | Состояние: установлено/готово/ошибки, сервер GNS3, кнопки «Открыть лабораторию», «Проверить», «Импортировать образы» (если образов ещё нет) |
| Установка | Мастер из 8 шагов (ниже) |
| Каталог | 186 компонентов, поиск и фильтры по категории, среде (QEMU/Docker/Dynamips/IOU), статусу |
| Проверка | Быстрая проверка файлов и шаблонов; «Проверить запуском» — создать/старт/консоль/стоп для каждого устройства |
| Восстановление | Повторно ставит повреждённые/удалённые образы и шаблоны (только то, что принадлежит VASYA) |
| Удаление | Мастер из 4 шагов (ниже) |
| Журнал | Человеческий журнал операций (Logs/operations.log) |
| Диагностика | ZIP с отчётом для поддержки (без паролей и личных файлов) |
| Инструменты | Wireshark, VNC, telnet, VPCS, Packet Tracer — найдено/нет и точная команда установки |
| Лаборатория | Демо-проекты (например OSPF + захват трафика) |

Язык (RU/EN) и тема (светлая/тёмная/системная) переключаются в нижней части меню.

## Мастер установки
1. **Добро пожаловать.** 2. **Проверка системы** — Python, KVM, Docker, uBridge, Dynamips, место на диске.
3. **Режим**: *Полная лаборатория* — собственный сервер GNS3 2.2.61 внутри папки VASYA (ваш GNS3 не трогается);
   *Интеграция* — добавить шаблоны в ваш GNS3 (резервная копия его конфигурации делается автоматически);
   *Выборочно* — только отмеченные компоненты.
4. **Компоненты**. 5. **Папка**. 6. **Что изменится** — место, загрузки, системные изменения с командами и
   способом отмены, нужен ли перезаход в сеанс. 7. **Установка** — прогресс по-человечески, «Отмена» безопасна
   (транзакция откатывается). 8. **Готово** — итог и проверка.

### Статусы компонентов
READY — образ скачивается автоматически с официального сайта; NEEDS_IMAGE — нужен ваш файл образа («Каталог → Импорт образа», sha256 проверяется);
NEEDS_DOWNLOAD — образ скачивается с сайта производителя; NEEDS_REGISTRATION / NEEDS_LICENSE — нужен аккаунт
или лицензия производителя; OBSOLETE / UNAVAILABLE — недоступно, причина указана в каталоге.
Компонент со статусом **BLOCKED** (например, openwrt-realview без `qemu-system-arm`) не считается ошибкой:
показывается нужный пакет и команда для администратора.

## Откуда берутся образы
Общедоступные образы скачиваются по адресам из `third_party.lock` и проверяются по SHA-256
(`vasya fetch --dry-run` покажет, чего не хватает и откуда это будет скачано). Образы производителей (Cisco IOS)
берутся только из вашего личного источника, см. PRIVATE_IMAGES.md. Устройство без образа помечается «образ недоступен».

## Импорт образов из личного офлайн-комплекта
Главная → «Импортировать образы» или `vasya import-payload --search`. Ищет `*.parts.json` в папке комплекта,
«Загрузках» и текущей папке, проверяет sha256 каждой части и каждого образа, распаковывает только образы и
манифесты в `<папка>/Store` атомарно (при ошибке ничего не меняется).

## GNS3 GUI (Linux)
Для графического GNS3 нужны PyQt6 и библиотеки `libxcb-cursor0` (+ `libxcb-icccm4`, `libxcb-keysyms1`).
`vasya gui-deps` показывает, чего не хватает. Недостающие xcb-библиотеки VASYA скачивает (закреплённые пакеты Ubuntu, SHA-256 проверяется) в
`<папка>/Runtime/lib` (без sudo, с квитанцией) — `vasya gui-deps --bundle`. В чужое окружение Python VASYA
PyQt6 не ставит — показывает команду.

## VPCS
Если `vpcs` (а также `dynamips`, `ubridge`) в системе нет, при установке VASYA скачивает сборку из GNS3 PPA
(версия и SHA-256 закреплены в `third_party.lock`) и кладёт её в
`<папка>/Runtime/bin/vpcs` и прописывается в конфигурацию сервера VASYA.

## Wireshark и VNC-консоли в GNS3 GUI
Установщик пишет собственный профиль GNS3 GUI для VASYA (`<папка>/Runtime/managed_gns3/xdg/config/GNS3/2.2/gns3_gui.conf`,
используется только при запуске GNS3 GUI из VASYA): захват трафика в Wireshark
(`tail -f -c +0b {pcap_file} | wireshark -k -i -`), VNC-консоль `vncviewer {host}:{port}` и путь к VPCS.
Ваши собственные настройки GNS3 не меняются.

## Что создаётся вне папки VASYA
vncviewer при первом открытии VNC-консоли создаёт `~/.vnc`. VASYA записывает это и показывает в отчёте удаления
(«Известные внешние побочные эффекты»); автоматически не удаляется.

## Windows
Менеджер работает, но устройства QEMU/Docker на Windows запускаются только через GNS3 VM (удалённый compute).
VASYA загружает образы на GNS3 VM и создаёт шаблоны; удалить их с VM автоматически нельзя — в отчёте будет
точная подсказка. **Статус Windows: НЕ ПРОВЕРЕНО** (см. SUPPORTED_PLATFORMS.md).
